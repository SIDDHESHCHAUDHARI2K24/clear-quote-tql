# P5/P6 foundation — Implementation plan

Shared groundwork for the P5 (LO Tier B, CQ-025–030) and P6 (Borrower Tier
B/C, CQ-031–034) parallel build, per `docs/backlog/phase-p5-p6-plan.md`
(H3, E1–E8, E14, E15, E17). No backlog item or Kaneo task owns this file;
it is the wave-1 unit (`p56-foundation`, slot 11) that lands before any
wave-2 worker starts. It contains no item features.

| 1 | Decision | Migration head | Decided: one migration `*_p5p6_foundation.py` with `down_revision = e419a34bcdbd` (the single head on `phase-p5-p6`). Every later P5/P6 migration chains off it. |
| 2 | Decision | `consents` pending rows | Decided: `text_hash`, `ip`, `at` become nullable (a pending request has no decision yet). New `status` enum `consent_status` (`pending`/`accepted`/`declined`/`expired`), `server_default='accepted'` so existing rows backfill as accepted, then the model default is `pending` for new rows. `requested_by` → `users.id` (indexed, `ON DELETE SET NULL`). | 7 | Decision | Flag messages (E8) | Decided: `flags.message` text nullable. `rules.py` gains `RULE_MESSAGES` + `flag_message(rule, field_key)` (static, human text per rule id, with a field label for `ob_required_field`, e.g. "Cannot price: missing Occupancy"). `write_flag(..., message=None)` stores the given message or falls back to `flag_message`; an existing unresolved row has its message refreshed. `run_and_persist` passes the rule's own dynamic `RuleResult.message` (e.g. "Only 14 months of housing history on file; 24 required."). The migration backfills existing rows with the same static text via SQL `CASE`. |

The activity writes no event and no status, and is registered as an internal activity next to `record_pipeline_resumed` (the six contract activities and their log line are unchanged). |
| 9 | Decision | `least_loaded_lo_id` (E15) | Decided: new `features/applications/assignment.py::least_loaded_lo_id(db)` counts *active* applications (status not `withdrawn`/`closed`) per LO (role `lo`), ties broken by `full_name` then `id`. `auth/borrower/service.py` imports it as `_least_loaded_lo_id` (old call site unchanged). | 10 | Decision | `core/clock.py` | Decided: `now()` returns `settings.clock_now` (parsed ISO-8601; naive values are taken as UTC) or `datetime.now(UTC)`. Reads `get_settings()` each call, so tests monkeypatch settings. New P5/P6 code uses it; old code is not refactored (E2). |
| 11 | Decision | `core/storage.py` | Decided: thin boto3 wrapper; each function takes an optional `bucket` (default `settings.s3_bucket`) and an optional `client` (default a cached boto3 client from `s3_*` settings). Async API (`asyncio.to_thread`) because every caller is an async service: `ensure_bucket`, `put_object`, `get_object`, `presigned_get_url`, `delete_object`; `stream_object` returns a sync chunk iterator (Starlette `StreamingResponse` iterates sync iterators in a threadpool). `seed/generators/documents.py` is **not** refactored: it threads its own client and bucket through `seed_persona`, so the change is not trivial. |
| 12 | Decision | `core/pagination.py` | Decided: `Page[T]` (pydantic generic: `items`, `total`, `page`, `page_size`); `async paginate(db, stmt, page, page_size) -> Page[Any]` returns ORM rows / scalars as `items` (callers map to their schema), clamps `page_size` to 1..100 (default 25) and `page` to ≥ 1. Count via `select(func.count()).select_from(stmt.order_by(None).subquery())`. Services are async, so this is too. |

No big gaps.

## Why

The 12 wave-2/3 item units run in parallel worktrees. Anything two of them
would both need — a schema change, a helper, an app shell, a UI primitive —
lands here first so they never edit the same file or fork `alembic heads`.

# P5/P6 foundation — Post-development notes

## Summary

One migration (`3b55187d53d7`, off `e419a34bcdbd`; `alembic heads` = 1)
adds `flags.message`, the consent request/decision columns, `support_requests`,
`application_drafts` and `applications.source`. New core helpers:

application.
