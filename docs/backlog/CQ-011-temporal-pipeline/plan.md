| 18 | Decision | `test_activity_events_sequence.py`/`test_resume_signal.py` order by `ActivityEvent.at`, not `.created_at` | `created_at` is `server_default=func.now()`, which Postgres resolves once per transaction — every event a single test's savepoint-bound activity sessions write (plan.md #12) shares one outer transaction, so `created_at` ties across a whole test's events; `ORDER BY created_at` then depends on incidental physical row order, which flaked once under full-suite load (`test_marcus_hale_happy_path_writes_6_events` saw `pipeline.enriched` before `pipeline.imported`). `ActivityEvent.at` is set Python-side (`datetime.now(UTC)`) by `activities._write_event` on every call and strictly increases between activities (each does real `simulate_latency` async sleeps), so ordering by it is reliable. Not a schema change — test-only ordering fix.

## Why

Every application needs the same automated import→verify→enrich→validate→price→draft chain, with retries, one visible run per application, and a resume path once an LO fixes a flag. This item wires that as one `ApplicationPipelineWorkflow` per `application_id`, backed by thin activities over CQ-012/CQ-013's already-built stage functions.
