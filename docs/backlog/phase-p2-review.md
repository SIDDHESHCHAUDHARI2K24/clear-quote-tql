### Minor

1. **`revert_field_value_route` has no dedicated auth-scope test.** `backend/app/features/pricing/enrichment/router.py:36-43` wires `revert_field_value_route` through the same `get_scoped_application` dependency as `patch_field_value`, but `backend/app/features/pricing/enrichment/tests/test_auth_scope.py` only exercises `patch_field_value` (401 without cookie, 404 for another LO's application, 200 for the owner/Manager). `test_field_value_override.py::test_revert_restores_source_value_and_clears_override` and `::test_revert_not_overridable_field_key_is_422` only cover the authenticated happy/validation paths. The wiring is correct by inspection (identical `Depends(get_scoped_application)`), so this is a coverage gap, not a known bug — suggest adding a `test_revert_field_value_401_without_cookie` / `test_lo_gets_404_on_other_los_application` pair (or parametrizing the existing `test_auth_scope.py` over both routes) so a future edit to the revert route can't silently drop the dependency without a test catching it.

2. **`seed_users` does not normalize the fixture email before storing it.** `seed/loader.py:144` sets `User(email=row["email"], ...)` directly from `seed/users.yaml`, while `backend/app/features/auth/staff/service.py:52` (`login`) always looks the row up via `normalize_email(email)` and `backend/app/features/auth/users/service.py::create_user` always stores through `normalize_email`. Today every address in `seed/users.yaml` is already lowercase with no surrounding whitespace, so login works, and `seed/tests/test_users_seeded.py` passes — but nothing enforces that invariant, so a future edit to `users.yaml` that introduces mixed case (e.g. copy-pasting `Jordan.Lee@…`) would seed a row that real staff login can never match (case-sensitive `User.email == normalized_email` in `backend/app/core/auth.py`'s underlying query and in `staff/service.py:56`), and the demo would silently break. Suggest `email=normalize_email(row["email"])` in `seed_users` for defense in depth, matching `create_user` and `seed_borrower_accounts` (`normalize_email(client.email)` at `seed/loader.py:216`, which already does this correctly).
