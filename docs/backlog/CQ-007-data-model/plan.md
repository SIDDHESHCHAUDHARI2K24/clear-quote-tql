# CQ-007 — Implementation plan

Written by the agent in stages 1–3. Do not start coding until every acceptance criterion maps to a test.

## Decisions & questions (stage 1)

Spec is unusually self-contained (exact table/column/enum names, migration slugs, settings defaults). Gap check found no big gaps. Small decisions, all already logged in spec.md and restated here for traceability:

| # | Type | Item | Resolution |
| --- | --- | --- | --- |
| 1 | Decision (from spec) | Enum placement | Cross-cutting enums in `core/enums.py`; feature-specific enums beside owning model, per spec table |
| 2 | Decision (from spec) | `FlagSeverity` semantics | `blocking` halts pipeline + blocks Send; `warning` is a tab-count only; `info` never becomes a `flags` row |
| 3 | Decision (from spec) | `settings` shape | Single key/value table (JSONB value), not typed columns |
| 4 | Decision (from spec) | `integration_calls` | Not in system-design.md's Data model table; added per spec for CQ-009/CQ-029 |
| 5 | Decision (from spec) | `employment` shape | Minimal shape (no catalog schema) — employer_name, monthly_income, years_at_job, self_employed, party_id |
| 6 | Decision (mine) | `alembic/env.py` online-migration engine | CQ-002 scaffolded `env.py` with a sync `engine_from_config`, but `DATABASE_URL` uses the `postgresql+asyncpg` driver, which a sync `create_engine` cannot load. Switched `run_migrations_online` to the standard Alembic async recipe (`create_async_engine` + `connection.run_sync(...)`) so `alembic upgrade head` works against the real async URL. Logged here since it touches a file CQ-002 authored, not a new file this item owns. |
| 7 | Decision (mine) | Model module imports for autogenerate | Added an explicit import block in `alembic/env.py` covering every model module (feature + integration) so `Base.metadata` is fully populated before autogenerate/`create_all` runs. Avoids a separate "model registry" module not mentioned in the spec. |
| 8 | Decision (mine) | `backend/conftest.py` | Spec/brief context says CQ-004's `Base.metadata.create_all` hands off to Alembic here. Switched `test_engine` fixture to run `alembic upgrade head` (via `alembic.config.Config` + `command.upgrade`, using `TEST_DATABASE_URL`) against `cq_test` instead of `create_all`, so tests exercise the real migration path. |
| 9 | Decision (mine) | Package scaffolding | New sub-feature packages (e.g. `applications/housing/`) get only `__init__.py` + `models.py` (+ `tests/`) this item — `router.py`/`schemas.py`/`service.py` are out of scope until the owning feature item adds them. |

## Why

Every later item (CQ-008 onward) imports these tables/enums by exact name. This item is the single place the full Postgres schema is defined so nobody downstream guesses column names, and it establishes the Alembic migration path CQ-004 deferred.
