# CQ-007 — Post-development notes

## Summary

Built the full Postgres schema (30 tables across 23 feature/integration `models.py` modules), every enum from the spec (`core/enums.py` for cross-cutting ones, feature-local otherwise, all rendered as native Postgres enum types via a new `pg_enum()` helper in `core/db.py`), and Fernet-based SSN encryption (`core/encryption.py`, `EncryptedString` `TypeDecorator`) with a fail-fast `Settings` validator requiring `FIELD_ENCRYPTION_KEY` outside `APP_ENV=test`. Two Alembic migrations: `initial_schema` (autogenerated from the models, hand-fixed for the `EncryptedString` import and for enum-type cleanup on downgrade) and `seed_settings_defaults` (hand-written data migration inserting the 16 documented default rows). `alembic/env.py` was fixed to use an async engine (the scaffolded sync `engine_from_config` can't load the `postgresql+asyncpg` driver) and now explicitly imports every models module so autogenerate/upgrade see the full schema; it also accepts a `config.attributes["sqlalchemy_url"]` override so `backend/conftest.py` can point migrations at `TEST_DATABASE_URL` instead of the dev DB. `backend/conftest.py`'s `test_engine` fixture now runs `alembic upgrade head` (via alembic's Python API, off the event loop in a worker thread) instead of CQ-004's `Base.metadata.create_all`.

## Deviations from spec

| Spec said | Built | Why |
| --- | --- | --- |
| (implicit) `alembic/env.py` from CQ-002 works as-is | Rewrote `run_migrations_online` to use `async_engine_from_config` + `connection.run_sync(...)` | The scaffolded sync `engine_from_config` cannot load the `postgresql+asyncpg` driver (asyncpg is async-only); `alembic upgrade head` would fail on every environment, not just tests |
| Autogenerated `initial_schema` migration, as-is | Added an explicit `import app.core.encryption` (autogenerate referenced `app.core.encryption.EncryptedString()` in the `application_parties` column but never imported the module) and added explicit `DROP TYPE IF EXISTS ...` statements for all 20 enum types at the end of `downgrade()` | Without the import, the generated file is a `NameError` at collection time. Without the enum drops, `downgrade base` leaves orphaned Postgres enum types behind, so a second `upgrade head` fails with `type "..." already exists` — this broke AC5 until fixed |
| conftest.py hands off to `alembic upgrade head` (spec/CQ-004 note) | Also added `os.environ.setdefault("APP_ENV", "test")` and `os.environ.setdefault("FIELD_ENCRYPTION_KEY", <generated>)` at the top of `conftest.py`, before any `app.*` import | `Settings` is `@lru_cache`d and instantiated at `app.core.db` import time; without setting these first, every test run would need a real `.env` with `APP_ENV=test` and a key already set, which isn't guaranteed in CI (CQ-006) |
| (n/a — new local dev requirement) | Created `.env` (gitignored, from `.env.example`) with a generated `FIELD_ENCRYPTION_KEY`, and added `alembic`/`cryptography` to `pyproject.toml` dependencies | Required to run `uv run pytest`/`alembic` at all — CQ-004 defined `Settings` fields with no defaults, so a `.env` (or equivalent env vars) is a hard prerequisite this item is the first to actually exercise; `alembic` and `cryptography` were never added as real dependencies despite the scaffolded `alembic/` directory and the spec's Fernet requirement |

## How to test manually

1. `make up` (starts the `clear-quote` compose stack: Postgres, Valkey, MinIO, Mailpit, Temporal).
2. `cp .env.example .env` and fill in `FIELD_ENCRYPTION_KEY` (e.g. `uv run python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`).
3. `uv run alembic upgrade head` — builds the schema on `cq_dev`.
4. `docker exec clear-quote-postgres-1 psql -U cq -d cq_dev -c '\dt'` and `-c 'SELECT key, value FROM settings ORDER BY key;'` to inspect tables/seed rows directly.
5. `uv run pytest backend` — runs the full suite (spins up `cq_test` via `alembic upgrade head` automatically).
